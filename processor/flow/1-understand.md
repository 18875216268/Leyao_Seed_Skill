# ① 理解

思路不清、资源不备，不动手。

## 输入

用户的原始需求（一句话或一段材料）。

## 出口判据（全过才进入规划）

- [ ] 一句话需求复述完成，用户可纠正
- [ ] 关键口径无未处理的 L3 歧义（L3 已列入询问清单）
- [ ] 承接资源已定位（可调资产 / 自带判据 / 需要用户补充的材料）

## 动作

1. **复述需求**：用自己的话重述用户要什么，一句话能说清。
2. **口径盘点**：列出关键口径（时间范围、范围主体、计算口径、交付形式），标注每项是"已明确 / 有假设 / 有歧义"。
3. **资源盘点**：读 `library/ROUTES.md`，拿任务场景逐条对照每个节点的**描述**（何时用）——有没有能承接的资产？没有就按自带判据亲做。命中节点后**记下它的 id**（交付步 `grow.py trace --routed` 要用）。**同读 `library/.memory.md`**：命中的「失效模式」要规避，命中的「有效做法」可直接复用。需要的输入材料在哪里？
4. **歧义分级**（判据自带）：
   - **L1 无关紧要**：任何解读都不影响验收 → 选最常见的，交付时说明假设；
   - **L2 可自行判定**：任务上下文/历史习惯能唯一确定 → 自行判定，交付时显式标注所采用口径；
   - **L3 需用户定**：多解读结果差异大且无法从上下文判定 → 汇总留待规划步集中询问。

## 红旗

- 需求名词未定义（"销售额"是含税还是不含税？）就往下走。
- 没查总路由就开始手搓。

## 引导（可裁量，非判据）

- **口径盘点的四个常见漏项**（用来自查，不是必答清单）：时间范围（截止时点/时区）、主体范围（谁的数据/含不含下级）、计算口径（含税与否/去重规则/退款取消是否计入）、交付形式（表/图/结论/文件）。
- **L3 的正例**：两种解读会让**交付物本身不同**——如"上月"指自然月还是滚动 30 天、"销售额"含不含税。
- **不是 L3 的情形**：只影响措辞或呈现顺序（→ L1）；上下文或历史习惯已能唯一确定（→ L2，但交付时要显式标注所采用口径）。
- **资源盘点的小技巧**：先拿任务里的**业务名词**去地图描述里对一遍，再按场景整体对一遍——只按任务类型（"查询/汇总"）对，容易漏。
