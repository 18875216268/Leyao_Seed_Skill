# ① 理解

思路不清、资源不备，不动手。

## 输入

用户的原始需求（一句话或一段材料）。

## 出口判据（全过才进入规划）

- [ ] 一句话需求复述完成，用户可纠正
- [ ] 关键口径无未处理的 L3 歧义（L3 已列入询问清单）
- [ ] 承接资源已定位（可调资产 / 自带判据 / 需要用户补充的材料）
- [ ] 会话首次：宿主常驻与版本检查已完成（或已按 `version/VERSION.md` 降级 / 提醒）

## 动作

1. **就绪检查**：按 `version/VERSION.md` 执行两项检查——宿主常驻 + 版本检测（时机 = 会话首次与每日 14:00 唤醒时各一次；异步、失败降级、同会话不重复；结果提醒用户）。
2. **复述需求**：用自己的话重述用户要什么，一句话能说清。
3. **口径盘点**：列出关键口径（时间范围、范围主体、计算口径、交付形式），标注每项是"已明确 / 有假设 / 有歧义"。
4. **资源盘点（判据：先词面、再语义、列候选）**：读 `library/ROUTES.md`，拿任务场景逐条对照每个节点的**描述**——
   ① **词面对照**：先拿任务里的**业务名词/别名**对各节点【别名】与【何时用】做一遍字面对照；
   ② **语义对照**：再按**场景整体**对一遍（只按任务类型对，容易漏）；
   ③ **列候选**：把**所有像的**节点列进候选集（含子节点；**宁多勿漏**，筛选留给 ③ 执行步）；候选为空 → 按自带判据亲做；
   ④ **核对输入前置**：每个候选的【输入前置】（凭证/材料）**是否拿得到**——拿不到的先记下（③ 据此降级或排除）；
   ⑤ **记下 id**：候选与依据都要留证（交付步 `grow.py trace --routed` 只用最终命中的 id）。
   **同读用户区记忆 `.leyao-data/data/memory.md`**：命中的「失效模式」要规避，命中的「有效做法」可直接复用。
5. **歧义分级**（判据自带）：
   - **L1 无关紧要**：任何解读都不影响验收 → 选最常见的，交付时说明假设；
   - **L2 可自行判定**：任务上下文/历史习惯能唯一确定 → 自行判定，交付时显式标注所采用口径；
   - **L3 需用户定**：多解读结果差异大且无法从上下文判定 → 汇总留待规划步集中询问。

## 红旗

- 需求名词未定义（"销售额"是含税还是不含税？）就往下走。
- 没查总路由就开始手搓。

## 引导（可裁量，非判据）

- **口径盘点的四个常见漏项**（用来自查，不是必答清单）：时间范围（截止时点/时区）、主体范围（谁的数据/含不含下级）、计算口径（含税与否/去重规则/退款取消是否计入）、交付形式（表/图/结论/文件）。
- **L3 的正例**：两种解读会让**交付物本身不同**——如"上月"指自然月还是滚动 30 天、"销售额"含不含税。
- **不是 L3 的情形**：只影响措辞或呈现顺序（→ L1）；上下文或历史习惯已能唯一确定（→ L2，但交付时要显式标注所采用口径）。
- **资源盘点的小技巧**：先拿任务里的**业务名词**去地图描述里对一遍，再按场景整体对一遍——只按任务类型（"查询/汇总"）对，容易漏。
- **先开放式、再收敛**（参考咨询的标准做法）：先用开放问题弄清"开场问题**背后**的真实需求"（你想解决什么 / 给谁看 / 什么时候要），再把它收敛成具体口径选项——**不要一上来就让用户在选项间选**。
