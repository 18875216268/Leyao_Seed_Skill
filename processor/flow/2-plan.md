# ② 规划

按最小充分口径给出方案；歧义集中询问；自检通过才执行。

## 输入

理解步的产出（需求复述、口径盘点、资源定位）。

## 出口判据（全过才进入执行）

- [ ] 每个规划项可追溯到需求原文；需求每个名词被承接
- [ ] 执行路线明确（调谁 / 怎么做 / 用什么命令），且**资产候选含【不适用条件】**（写清什么情况下不用它）
- [ ] **计划已阶段化**：按阶段（= 交付/子目标自然分解）给出「阶段 × 子任务 × 资产（或亲做）× **必须/可选** × 前置 × 该阶段出口判据」；**可选项必须写启用触发条件**（执行中按条件再定要不要，不预支调用）
- [ ] **多阶段 / 长任务**（≥3 阶段或预计调用多）：已产出**需求契约表**（用户原话逐条 → 承接阶段 → 证据指针 → 状态）并写入 `过程记录.md`（形状见 `processor/shapes.md` 第 8 节）；单阶段小任务**不要求**（避免官僚化）
- [ ] **验收 rubric 已定**（多阶段/长任务，或"做得好不好"可能扯皮时）：把"**什么算做得好**"写成 **3–5 条可判定项**（每条能被第三方按文档核对真假），供 ④ 逐条对照——契约表管"做没做"，rubric 管"**好不好**"（依据：AdaRubric「先显式写评分量规，再评」）
- [ ] **不可逆步骤已前置标识**：计划中凡「删除 / 覆盖 / 对外发送 / 产生费用 / 不可回滚」的步骤，**逐条标出并列入"执行前须用户确认"点**——把红线「不可逆动作前置确认」从执行期**提前到规划期**（执行时漏确认 = 红线违规）
- [ ] **事实与猜测分开**（事实=有出处；猜测须在验收前落实或显式标注）
- [ ] **上限已定**（预计调用次数或时长；超限即停止并如实报告——见 `processor/control.md`）
- [ ] `<work-dir>` 已确定、**四区已建齐**（原始材料/任务执行/结果交付/归档），并在留证中明示
- [ ] 无未决 L3（已获用户决定）

## 动作

1. **口径规划**（最小充分口径）：列出方案每一项并逐项对应需求原文；每项必须满足其一才保留——**① 需求直接要求 ② 缺失即验收失败 ③ 成本近零**；三条都不满足 → 砍掉（预防"过度规划"与"隐形缩水"）。
2. **执行路线 + 工作目录**：① 每个子任务标注路线——调资产（写明 id 与调用方式）/ 亲做（写明依据的判据）；**并汇总为阶段化计划表（硬）**，列：`阶段名 ｜ 子任务 ｜ 资产 id（或"亲做"）｜ 必须 / 可选（可选→写启用触发条件）｜ 前置（凭证/文件/口径）｜ 该阶段出口判据`——阶段按**交付物的自然分解**切（如"取数 → 校验 → 分析 → 呈现"），每阶段**独立可验收**（实践依据：长程任务的"子目标驱动 + 在线规划"——阶段即子目标，便于局部回退）；**多阶段/长任务同时把用户原话落成「需求契约表」**（同表结构加"需求原文 / 承接阶段 / 证据指针 / 状态"四列，写入 `过程记录.md`）——防"中段细节冲淡原始需求、完成局部就宣告完成"；② 确定 `<work-dir>`（**用户指定优先**；未指定则建 `work-<YYYYMMDD>-<任务短名>/`，一任务一工作区）并**在留证中明示**；③ **建齐四区**（结构模板见 `processor/shapes.md`）：
   ① `01-原始材料区/`（用户材料，只读）· ② `02-任务执行区/`（`过程记录.md` ＋ `临时产物区/`）· ③ `03-结果交付区/`（只放最终件）· ④ `04-归档区/`（历史/不适用/过时，不删除）。
   根目录只放这四个区（可选一个 `README.md` 写一句话任务说明）；`过程记录.md` 从模板起手：`processor/templates/过程记录.md`。
   ④ **定上限**（预计调用次数或时长）与**回退预算**（宁紧勿松，留痕即可）；⑤ 标注**资产候选的【不适用条件】**与**事实 / 猜测**（猜测=待验证，验收前必须落实或显式声明）。
3. **L3 歧义集中询问**：一次任务**最多一轮**集中询问——把全部 L3 汇总成一个清单，每项给 2-3 个选项、每个选项一句话说明差异与后果、附默认建议；用户决定后记入交付说明。**禁止用"默认值"悄悄吞掉 L3**——悄悄吞掉会让方向偏差拖到验收才暴露，返工成本最高。清单形状见 `processor/shapes.md`。
4. **自检（硬）**：逐条核对上面的出口判据；未过 → 调整后再判（最多 5 轮），仍不过 → 交用户共同讨论（给候选方案优缺点与推荐）。

## 红旗

- 规划里有"顺便也可以做"的项（过度规划）。
- 需求名词悬空无承接（隐形缩水）。

## 引导（可裁量，非判据）

- **"≥95% 把握 / ≥90% 满意度"是感受性说法，不可测量，故不作判据**；它的可核对代理就是出口判据本身。
- **砍项时的常见误判**："顺手也能做"（→ 砍）、"客户可能想要"（→ 除非需求原文支持，否则砍）、"先做上、交付前再删"（→ 砍，过程成本也是成本）。
- **路线选择的三条经验**：能调资产就别亲做（资产是已验证过的做法）；能一步算就别拆两步；不确定的事**前置探明**（把不确定性放在最便宜的地方）。
- **询问清单的排序**：把"答案会改变方案骨架"的放前面、"只影响细节"的放后面——用户答完前几条，后面的常会自动消失。
