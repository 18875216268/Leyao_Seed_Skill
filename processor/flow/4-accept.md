# ④ 验收

对照需求逐项验收；不合格回到执行步，不硬交。

## 输入

执行步的产物与留证（关键产物路径 / 命令 / 来源、失败记录）。

## 出口判据（全过才进入交付）

- [ ] 需求逐项验收通过
- [ ] 关键数字复核一致（换一种方式再算/再查）
- [ ] 口径标注完整
- [ ] 无"编造平滑"（不确定处已显式声明）
- [ ] **红线单列**：不可逆未确认 / 静默操作 = **0**（逐项核对，不混入总分）
- [ ] **过程成本已记录**：循环次数 / 回退次数（与规划上限对照；成功但超预算不算通过）
- [ ] **需求契约表逐条闭环**（多阶段/长任务）：每条需求状态 = 完成 或 放弃（含原因）；**不得留"进行中"**

## 动作

1. **逐项对照**：需求原文的每个名词/口径，交付物里都有对应结果吗？
2. **数字复核**：关键数字复核一遍（换一种方式再算/再查），两次一致才采信。取法见引导。
3. **口径核对**：每个数字带口径标注（时间范围/主体范围/含税与否）了吗？形状见 `processor/shapes.md`。
4. **诚实检查**：事实与推断分开了吗？有缺口的地方显式说明了吗？

## 红旗

- 验收发现缺口却选择"先交付再说"。
- 用平均/估算悄悄填补缺失数据。

## 引导（可裁量，非判据）

- **"换一种方式"复核的取法**（三选一即可，不必都做）：改口径算（换时间粒度/过滤条件，看量级是否同向）；改来源查（另一张表/另一个人，看是否一致）；改方法算（明细加总 vs 直接取汇总）。两次不一致时**以明细为准并查明差异**（判据）。
- **口径标注的常见漏项**：含税与否、去重规则、退款/取消是否计入、时区与截止时点。
- **"编造平滑"的典型形态**：用均值补缺失、用同比替代实际值、把"无数据"写成"约为 0"、把推断值当实测值写。
- **对照 rubric（多阶段/长任务）**：逐条核对规划期定的"验收 rubric"（3–5 条可判定项），每条给**证据**或标"未达标"——只对照需求清单不够：**"做了" ≠ "做好了"**；未达标要么补做、要么在交付说明里显式声明为已知差距（不静默降级）。
- **交付前红队自审（一条即可，非判据）**：如无十足把握，先问自己"**别人最可能挑哪一点**"——把这一点连同证据（或"不确定，已标注"）写进 D 区，再决定是否补做；**只为防看不见的盲点，不要求列满清单**（列满=形式主义）。
