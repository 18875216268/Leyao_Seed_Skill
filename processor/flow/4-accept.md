# ④ 验收

对照需求逐项验收；不合格回到执行步，不硬交。

## 输入

执行步的产物与留证（关键产物路径 / 命令 / 来源、失败记录）。

## 出口判据（全过才进入交付）

- [ ] 需求逐项验收通过
- [ ] 关键数字复核一致（换一种方式再算/再查）
- [ ] 口径标注完整
- [ ] 无"编造平滑"（不确定处已显式声明）

## 动作

1. **逐项对照**：需求原文的每个名词/口径，交付物里都有对应结果吗？
2. **数字复核**：关键数字复核一遍（换一种方式再算/再查），两次一致才采信。取法见引导。
3. **口径核对**：每个数字带口径标注（时间范围/主体范围/含税与否）了吗？形状见 `processor/shapes.md`。
4. **诚实检查**：事实与推断分开了吗？有缺口的地方显式说明了吗？

## 红旗

- 验收发现缺口却选择"先交付再说"。
- 用平均/估算悄悄填补缺失数据。

## 引导（可裁量，非判据）

- **"换一种方式"复核的取法**（三选一即可，不必都做）：改口径算（换时间粒度/过滤条件，看量级是否同向）；改来源查（另一张表/另一个人，看是否一致）；改方法算（明细加总 vs 直接取汇总）。两次不一致时**以明细为准并查明差异**（判据）。
- **口径标注的常见漏项**：含税与否、去重规则、退款/取消是否计入、时区与截止时点。
- **"编造平滑"的典型形态**：用均值补缺失、用同比替代实际值、把"无数据"写成"约为 0"、把推断值当实测值写。
