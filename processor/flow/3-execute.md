# ③ 执行

按规划逐步执行；查总路由调用资源；全程留证、实时纠偏。

## 输入

规划步的产出（子任务路线、`<work-dir>`、已决 L3）。

## 出口判据（全过才进入验收）

- [ ] 规划的每一项已执行或有明确的失败记录与原因
- [ ] 关键产物已留证（路径 / 命令 / 来源）并按**四区**落位（过程记录与临时产物落在 `02-任务执行区/`）
- [ ] 无未处理的 medium/high 偏差
- [ ] 循环已收敛（满足即停，或触发上限后已如实报告）；**停止 / 回退理由已留证**

## 路由判据（选谁做 · 按序比对，不得跳步——跳过前置比对会直接选错资产）

**两阶段**：**1a 圈候选（宁多勿漏）→ 1b 筛候选（宁准勿错）→ 2 命中 → 2.5 复核 → 2.6 必要性**；多候选一律交用户。

0. **先查经验**：读用户区记忆 `.leyao-data/data/memory.md`——任务场景命中「失效模式」的资产先规避或换法；命中「有效做法」的直接复用；再看近期轨迹（同类任务的既有选择与结果）。
1a. **圈候选（宁多勿漏）**：拿任务场景逐条读 `library/ROUTES.md`——**先按业务名词/别名做词面对照，再按场景做语义对照**，把**所有像的**节点（含子节点）列成候选集；候选为空 → 直接判据 3。
1b. **筛候选（宁准勿错）**：用【不适用】**排除**明显不符；用【输入前置】判**可行性**（凭证/材料拿不到 → 排除或降级）；用【时效性】判**硬约束**（如"只到前一天" vs "要当天实时"）。
   **父子同时成立时按"贴合度"取一个**：子节点是父的**专项优化**——任务需要该专项（如"当天实时""出库统计自定义"）→ 取子；任务只需父的一般能力 → 取父；贴合度相当 → 取子（更专门）。子节点【不适用】命中 → 回退父级。
   ⚠️ **排除要读语义、不要按词面**：资产在【不适用】里以"**非 X / 不做 X / 非 X 域**"的形式提到 X 时，**不等于** X 不能用；同理，【输入前置】写"**无需凭证**"是**不需要**凭证，别当成需要。一律按整句语义判断。
1c. **覆盖核对（宁全勿缺）**：把任务的**核心需求**逐条列出（如"当天实时" + "自定义聚合" + "含税口径"），核对每条**是否被某个剩余候选的【何时用】覆盖**；出现"**无人覆盖**"的需求 → 按判据 4 处理（问用户：可能需要**组合调用**多个资产，或调整口径）。
2. **命中资产**：候选**唯一** → 进它的 `→ 挂载` 目录，先读其 `SKILL.md`（无则 `README.md`）看触发条件与用法，然后**原样调用**，不改其文件（改了资产就失去可复现性与后续升级能力）。入口文档**两者皆无** → 视为该资产不可用，退回判据 3 亲做，并在交付后提案补入口文档（引擎只作**软提示**、不判问题——资产可放任意内容，资料型资产无需入口文档）。
2.5. **命中复核（硬 · 主动证伪）**：读到资产文档后，用它的【触发条件／不适用】**反过来核对本任务**——自问"**我能不能举出它不适用的反例？**"；举得出 → **退回判据 3 亲做**，并留证；举不出 → 通过（这一步就是"名实相符"的核实：名（文档声明）与形（本任务实际）对上才算命中）。
2.6. **必要性自问（硬 · 反向门）**：自问"**本任务调用该资产是否必要？**"——若能凭自带判据同样完成、且调用只增成本/风险，则为不必要 → 记决策后按判据 3 亲做（实测数据：工具/资产调用中约三成属不必要）。
3. **无资产命中**：直接按本层自带判据亲做（五步判据见 `flow/1~5`，偏差与红线见 `control.md`）——**不依赖任何资产**。
3.5. **能力获取阶梯（硬 · 顺序，不得跳级/不得缺级硬凑）**：需要某项能力而手头没有时，按序取用——
  ① **方法论优先**：路由面若有贴合本任务的「方法论」类资产 → 先按其执行（有方法，不硬做）；
  ② **现成资产**：判据 1a~2 命中即原样调用；
  ③ **按需获取工具/技能**：无现成资产 → 循 `bvix9o` 公共套件的获取指引与 `find-skills`（技能导购：**先本地技能市场 → 后联网搜 → 验落位再用**；GitHub 不可达转 `fmcq5n` 通道）；**装完验通才用**，取得失败即如实降级，不硬凑；
  ④ **先调研再动手**：领域/方法不确定（无方法论、无资产、无现成技能）→ **先做一次轻量调研**（公开文档/联网资料/同类实践），产出「要点 + 来源 + 采用与否」记入 `KI-nn`，再定方法；
  ⑤ **亲做 + 提案**：以上皆不成立 → 按判据 3 亲做，交付后记「缺什么能力」并按判据 5 提案（供下次变成资产）。
  任一级「用后效果不好」→ 按动作 5 换路（换参数 → 换源 → 换工具走 `control.md` 回退）。
4. **多候选 / 覆盖不全（≥2 个都成立，或某核心需求无人覆盖）**：**必须问用户**（**禁止**自行裁决"谁更贴合"）——附选项、差异与后果、默认建议（形状见 `processor/shapes.md`）；**可选方案里可以包含"组合调用"**（如 A 出实时数 + B 做聚合），并说明组合的口径风险；用户决定后记入决策记录。**门槛初值取保守（少误选优先）；"过度询问"同样算缺陷**，后续按轨迹校准（见引导）。
5. **全不命中**：按自带判据亲做，并记下"缺什么能力"，交付后用 `python evolution/grow.py propose --kind asset_write --payload '<JSON>'` 提案（缺路由用 `route_update`、缺阈值调整用 `meta_update`），经用户批准后 `grow.py apply --id <p_x>` 落地。

## 动作

1. **按路线执行**：规划定的路线不改——调资产就原样调（不改其文件），亲做就按自带判据做。
2. **实时控制**：每步对照 control.md——偏差 low 记录 / medium 暂停确认 / high 阻断；安全红线不可越过。
3. **留证 + 过程记录（活文档）**：① 关键中间产物与数据来源随手记录（文件路径、命令、数据出处），按规划步定的 `<work-dir>` 落到四区（agent 产生的一切只在 `02-任务执行区/临时产物区/`，不在其它地方）；② **每完成一个关键动作，立即往 `02-任务执行区/过程记录.md` 追加**：进度一行（SOAP 式）+ 命中/新增的 `KI-nn`（含口径与来源）+ 决策 `D-nn`（含被排除项）+ 产物指针 `P-nn`——**实时写，不攒到最后补**（延展心智：外置记忆必须实时耦合）。阶段完成后折叠：细节入 `04-归档区/过程记录-<阶段>.md`，主记录留一行指针。最小集见引导。
   ③ **路由决策必留证**：每次路由（选资产/问用户/亲做）都在 D 区记一条，格式见 `processor/shapes.md` 第 6 节——**候选 / 判定依据 / 结论（含是否复核通过）/ 四格归类 / （若误选）成因**；没有这条，事后就无法审计与校准门槛。
   ④ **阶段出口勾选 + 尾部重述（多阶段/长任务）**：每完成一个阶段，立即更新「计划表状态 + 需求契约表状态」（完成 / 放弃+原因），并把「**本阶段结论 + 剩余计划 + 需求状态**」**重述写进过程记录尾部**（利用上下文"近端"优势对抗漂移——依据 Goal Recitation：定期把目标/待办/状态重写到上下文尾部），同时回看一句"**全局目标此刻仍成立吗、用户需求有无变化**"——防"子目标当整体目标、完成局部就宣告完成"（依据：Goal Drift / Inherited Goal Drift / Premature Completion 反模式）。
4. **遇到新字段/新参数**：可用即可用；交付后用 `python evolution/grow.py propose --kind asset_write --payload '<JSON>'` 把新用法补进该资产的文档（与判据 5 同一条提案路径，经用户批准后 `apply` 落地）。
5. **工具循环三要素（硬）**：每次调用都按 **调用 → 校验（出口判据）→ 换路再试 / 满足即停** 推进：
   - **校验**：用该步的判据判断"这一步成立吗"（数据/文件/接口返回），不留待最后；
   - **换路顺序**：换参数（范围/口径/粒度）→ 换源（同类资产 / 备用通道）→ 若需**换工具（即改路线）**，按 `control.md`「回退与重走」处理，不擅自改；
   - **满足即停**：判据通过立即停止该循环，**停止理由写进留证**（不继续堆调用）；超上限或判停滞 → 按 `control.md` 停止或回退。

## 红旗

- 偏差发生不记录、继续跑。
- 绕过总路由直接手搓已有资产覆盖的能力。
- 无判据地重复同一调用（既不停、也不换路）。

## 引导（可裁量，非判据）

- **多候选的比较维度**（判据 4 只说"更贴合"，这里给可操作的看法）：① 描述点名的场景与本次任务重叠多少；② 资产的输入要求与手上材料差多少；③ 同类历史轨迹的结果（用户区记忆 `.leyao-data/data/memory.md`）。三项都拉不开差距 → 按判据 4 问用户。
- **"原样调用"的边界**：不改资产文件，但**可以**按其 `SKILL.md` 允许的参数/开关调用；文档里没写的用法，先小样试跑再全量。
- **留证的最小集**：数据来源（表名/文件/接口）、关键命令、口径假设、异常与处理方式——缺这四样，验收步必返工。
- **失败记录的写法**：写"在哪一步、期望什么、实际什么"，不写"失败了"。
- **资产的两条使用准则**（软引导，见 `processor/PROCESSOR.md` 的「资产使用准则」）：① 资产优先但不强求——尽可能多用资产层已有资产，确实不需要则无需强行套用；② 需要时可**循资产文档的指引再获取更多资产**，取得后按判据 2 使用；新资产进资产层走维护流程（不在任务中私改）。
- **归属三问**（把任何一份东西放进四区前问一遍，避免 PARA 式的"边界模糊"）：① 是用户给的材料？→ `01-原始材料区/`；② 是我产生且未定稿？→ `02-任务执行区/临时产物区/`；③ 是最终交付件？→ `03-结果交付区/`；④ 已过时 / 不再需要？→ `04-归档区/`。四问都不像 → 先放临时产物区并在过程记录里说明（不硬塞、不新建区）。
- **过程记录的三类锚点**（长任务定向召回的索引）：`KI-nn` 关键信息（事实 + 口径 + 来源）· `D-nn` 决策（含被排除方案与理由）· `P-nn` 产物指针（路径 + 用途 + 状态）。后续任何步骤引用关键信息**只写锚点**（如"按 KI-03 的口径"），需要时按锚点回读，不重读全部历史。
- **搬移用户材料的可逆性**：把任务根内散落的材料归位（→ `01-原始材料区/`）前先列**将移动清单**并记下**原路径**（写进过程记录的 D 区），移动后校验大小；同名不覆盖（加 `-v2`）。**任务根之外的用户目录一律不动**（要动须用户确认）。
- **候选集要如实呈现**（软引导，但非常有用于自查）：候选可按"集合"理解——**单元素**（唯一强命中）→ 直接走；**多元素**（≥2 都成立）→ 问用户；**空集**（无命中）→ 亲做 + 提案。把候选集写进 D 区，事后一眼能看出"当时像的有几个"。
- **新资产探索位**：候选里若有**新挂载或久未使用**的资产，保留 1 格并**标注"新资产、未验证"**（把探索的风险显式交给用户，而不是悄悄绕过它）。
- **三档取信息**（省上下文且更准）：圈候选时只看**名称/标题**；筛选时看**名称+描述**；**只有到复核那一步才读完整资产文档**（触发条件/用法/输入要求）。
- **复核的话术**（2.5 的实操）：别问"它适用吗"（含糊描述几乎总能被解释为适用），要问"**有没有反例能推翻它适用**"——例：资产声明"实时性较强"，而你手上只拿到 T+1 的输入 → 反例成立 → 退回亲做。
- **门槛校准**（长期）：初值保守（≥2 都成立就问用户）；把"**过度询问**"（本可直接走却问了）与"**误选**"（本不该走却走了）都记进 D 区四格——**积累后据此放宽或收紧门槛**，而不是凭感觉调。
- **"小样试跑"的默认量级**（量级是引导；"先小样后全量"是判据，见动作 1）：取**能暴露字段与口径问题的最小样本**——单主体或单日、≤100 行即可；小样通过标准 = 字段齐备 + 无报错 + 与全量口径描述一致，三者任一不过就先修用法再全量。
