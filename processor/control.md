# 实时控制与纠偏（贯穿五步流程）

**全链路**（就绪巡检 · 路由 · 执行 · 资产内部 · 验收 · 交付 · 更新等任何环节）的偏差分级、纠偏与卡壳处置规则（各环节特有的失败路径仍以各自文档为准）；本文件给**通用处置**。**本文件即判据来源**（任务处理层自带，不依赖任何资产）。
本文件全部为**硬判据**（分级、裁决、红线），无可裁量项；准则硬度约定见 `processor/PROCESSOR.md` 的「判据分级」。

## 偏差分级（执行时逐条对照）

| 级别 | 判据 | 动作 |
| --- | --- | --- |
| low | 不影响交付口径与结论 | 记录到执行留证，继续 |
| medium | 影响部分交付物或口径 | 暂停 → 向用户说明 → 给修正选项 → 按决定继续 |
| high | 触及需求本身 / 安全红线 / 不可逆动作 | 阻断 → 必须用户确认后才能继续 |

## 双准绳裁决（有冲突时）

1. 本轮明确需求（intent）优先于一切历史习惯；
2. 无本轮明确信号时沿用用户长期习惯；用户本轮明确改变习惯除外。

## 安全红线（任何级别不可越过）

- 不静默：删除 / 移动 / 覆盖前先说清并获得确认；未确认事项先问，不替用户假定——静默操作不可审计、不可回滚。
- 先证明后删除：撤除任何资产前先验证替代路径可用——先有替代，才敢撤除。
- 歧义不代选：L3 歧义交用户决定——代选等于替用户承担他没有授权的风险（用户以"赶时间/你定"要求跳过时，**仍须一轮集中询问并附默认项请其一键确认**，不得静默代选 ✗）。
- 不可逆动作前置确认：不可逆动作没有回滚窗口，所以确认必须在动手之前。

## 推进控制（循环 · 上限 · 停滞 · 回退）

以下四条为**硬判据**（可被第三方按文档核对）：长任务必须"能推进、会停、卡了能报警、错了能回来"。

### 1. 循环上限（硬）

- 规划步必须为任务声明**上限**（预计调用次数或时长）；执行中不得突破。
- **超限动作（硬）**：立即停止循环 → 如实报告三件（已试路径 / 实际现象 / 下一步建议）→ 不得静默继续、不得把已试结果当结论交付。
- 上限数值由规划定（宁紧勿松）；**本文件不写死数字**（避免凭空阈值误杀）。

### 2. 停滞检测（硬）

**停滞判据**：连续 **2 步**满足任一条件即判停滞——
① 同一调用的结果与上次**等价**（无新增信息）；② 校验判据仍未通过且**无新假设**；③ 只有解释性输出、**无状态改变**（无新产物 / 无新数据）。

- **停滞动作（硬）**：停止继续重试 → 触发**回退**（见下），而不是第 3 次做同一件事。
- 停滞与偏差分级是**两个维度**，不混用：偏差=与预期不符（low/medium/high）；停滞=没有进展。

### 3. 回退与重走（硬）

| 触发 | 回退到 | 必须留痕 |
| --- | --- | --- |
| 停滞（上节） | ② 规划 | 停滞证据 + 新计划要点 |
| 判据冲突 / 口径不明 | ① 理解 | 待澄清问题清单（必要时问用户） |
| 资产不匹配 / 不可用 | ② 规划（换源或按自带判据自做） | 已试资产与失败现象 + 替代方案 |
| 验收不通过 | ③ 执行 | 差距清单（判据 vs 实际） |

- **约束（硬）**：① 回退必须在过程记录留痕（D 条目）；② 重走阶段时**复用已验证结论**，不推翻已确认项；③ **回退次数计入上限**（防"回退死循环"）。
- **最小回退原则（硬）**：回退**只重走受影响的阶段 / 子任务**；受影响面以"该结论的下游依赖"界定并写进 D 条目（影响面）；**不受影响阶段的已验证结论与产物一律复用、不重做**——避免"一处不对、整轮重来"的成本浪费。
- **计划版本留痕（硬）**：计划每次调整记一条 D 条目——`计划 v(n) → v(n+1)`：触发（停滞/偏差/资产不可用/用户改需求）+ 改了哪几个阶段-子任务 + 影响面 + 复用了什么；**可选项的启用/放弃同样留痕**（含未启用的原因）。
- **边界（硬）**：执行步**不得擅自改规划路线**（那是回退，不是"顺手改"）——规划内的**换参数 / 换源**可在执行步直接进行，换**工具（改路线）**须按本表回退。

### 4. 卡壳处置（任何环节 · 硬）

**默认阶梯**：下列三步对**任何环节、任何形态的前置失败一概通用**（归因 A / B 类；**命中判定走判据链**，机械失败走本节阶梯 ✓）；某环节**另有专属处置者以专属为准**（就绪与更新见 `version/VERSION.md`；路由**选型**见 `flow/3-execute.md` 判据 2 / 2.5——**读取 / 取数等前置失败一律以本节为终点** ✓）——两者只择一，不并跑 ✗。

**定性先行**：单点失败先判「**可解决**（信息在场、仅 A 方法 / B 通道受阻）」还是「**不可抗力**（必要信息确实缺失 / 超权限 / 环境确已不可恢复）」——**单点工具失败 ≠ 不可解决** ✗。
- **先自查遗漏（硬）**：定性 / 换法之前，先回查**是否漏读指引、漏执行既有步骤**（如漏读资产 `SKILL.md`〈登录〉段、漏跑其只读验证）——**补读补验后多数「问题」自解**；**漏读类不得归「不可抗力」、不得直接问用户** ✗。

- **可解决 → 三步换法，不得放弃**（每步留证）：
  ① **换读法**：按**已知路径直读**（描述 / 索引 / `SKILL.md` 给出的路径即直读目标）——**不依赖搜索 / Glob / 通配** ✗；宿主的文件能力不可用 / 行为异常时 → 用直读工具 `python library/asset.py read <相对路径>`（相对包根 · 只读 · 带读取凭据 ✓；另有子命令 `resolve`（给挂载）与 `list`（列目录））；
  ② **换工具**：Read → shell（`type` / `ls` / `dir` / `Get-Content`）→ 脚本接口（`python` / pathlib / 资产自带 CLI）→ 宿主等价能力；
  ③ **换通道**：远端不可达 → 既有降级（如 `fmcq5n` 连通通道）或本地副本；更新链路的失败路径按 `version/VERSION.md`。
- **凭证 / 登录类缺失（专属落点 · 不空转三步）**：**直接调用资产 `SKILL.md`〈登录〉入口**（先跑其只读验证：有效即复用；失效按其入口登录），按 `processor/PROCESSOR.md`〈资产使用准则〉④ 执行；**未验证不得向用户索要** ✗。
- **不可抗力 → 列选项问用户**（形状见 `processor/shapes.md` 第 9 节〈卡壳处置卡〉）：A 换法继续 / B 如实降级交付（标注缺口与偏差）/ C 等输入后再继续——**附默认项请其一键确认**。
- **形式判据（硬 · 按「形式」适用；文中示例仅供参考，**非穷举** ✗ 不得以「不在示例里」规避）**：凡命中下列**形式**即适用——
  ① **前置充分性**：进入下一步 / 动手前，其**必需输入**（信息 · 参数 · 口径 · 素材 · 凭证 · 授权 · 工具 · 通道…）必须**已取得**；未取得 → 走本节换法与定性，**不得跳过** ✗（示例：读取失败、取数失败、凭证过期、缺参数、缺授权…）；
  ② **失败归因（三分类）**：任何失败先归因到 **A 方法 / 工具链**（可解决）· **B 通道 / 环境**（可解决；**环境失败先按可解决处理**，确证不可恢复再归 C ✓）· **C 信息本身不存在 / 超权限 / 不可抗力**；**不得把 A / B 当 C** ✗；放弃 / 降级 / 替代的决定**必须写明归因类别与依据**（供复核）；
  ③ **声明一致性**：凡「按 X 执行 / 已满足 Y / 符合 Z 口径」的**任何声明**，须与被引用对象的实际内容**逐项对齐**并可留证复核；**部分 / 近似 / 替代 / 降级**一律显式标注（缺口 + 影响面）✗（示例：部分采用方法论、近似数据、替代来源…）。

### 5. 决策卡点（硬 · 同一问题 3 轮仍不能决 → 问用户）

**判据**：**同一决策点**（同一问题 / 同一选项集）**连续 3 轮**分析或尝试后，仍**既不能证成也不能证伪**、且**无新增信息** → 判为决策卡点。

- **动作（硬）**：**停止自决** ✗ → 一轮集中询问：已试路径 + 已知事实 + **选项 A / B / C 及各自影响面**，并**附默认项**请其一键确认（形状见 `processor/shapes.md` 第 9 节）。
- **不得**第 4 轮继续自决、也不得静默代选 ✗；确无选项时，如实说明「无法推进」并给建议下一步。
- **与相邻判据的分工（不混用）**：**停滞（§2）**＝没有进展 → 回退重走；**循环上限（§1）**＝次数 / 时长超限 → 停止并如实报告；**决策卡点（本节）**＝有进展但**判不了** → 问用户（`flow/2-plan.md` 的「自检最多 5 轮」是自检循环上限，对象不同 ✗）。

## 上下文预算（长任务 · 硬）

长任务的失败常不在推理，而在工作记忆"太长、太吵"（证据：Context Rot / Offload-Summarize-Isolate）。三条硬要求：

1. **指针化**：大产物（长日志/大表/网页正文）**落盘到 `02-任务执行区/临时产物区/`，上下文中只留路径与一句话摘要**——不整段回显（可逆卸载，需要时回读）。
2. **折叠**：阶段完成即按模板折叠（细节入 `04-归档区/过程记录-<阶段>.md`，主记录只留指针行）——主记录保持"活判据可读"。
3. **隔离**：**长而独立的探索性子任务**（多源检索、批量比对）可隔离执行（子代理/独立脚本），**只回传摘要与产物**，不让过程噪音回流主线程。

> Cache（稳定前缀）属宿主侧优化，本层不设判据 ✗（不在我们控制范围内，写了也不执行）。
