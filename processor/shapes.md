# 形状模板（按需读 · 引导级，非判据）

> **性质**：以下都是**引导**——照抄可以让表达更清楚，**但不是判据**；不用它们不影响验收。
> **何时读**：需要向用户提问、需要标注口径、需要写交付件时。
> **为什么单独放这里**：常驻的准则只放判据（保持精简），形状随用随取（渐进披露）。

## 1. 询问清单（② 规划 · L3 集中询问）

硬要求（在 `flow/2-plan.md` 动作 3）：每项 **2-3 个选项 + 差异与后果 + 默认建议**；一次任务最多一轮。

```text
【问】<L3 问题原文，一句话>
  A. <解读> —— 差异：改变哪部分结果；后果：影响哪个交付物
  B. <解读> —— 差异：…；后果：…
  → 建议 A（一句话理由）；你也可选 B 或给第三解
```

## 7. 路由节点描述（**推荐**模板 · 非门槛）

> ⚠️ 本模板由 `library/engine.py`（描述形态标注）与 `processor/` 文档共同引用；改本节点请重绘
> `library/ROUTES.md` 并跑 `python evolution/tests/run_route_drill.py`（A 组会查此处）。

**性质**：写法**随你**——自由文本合法，**写入不拦截**（CLI 与管理台一致）。
六段齐备只是**路由能力等级**：判据链（`flow/3-execute.md` 的路由判据）能读到的字段越多，判定越准。

| 形态 | 判据链能力 | 系统行为 |
| --- | --- | --- |
| **structured**（六段齐备） | 全能力：词面命中 → 【不适用】排除 → 【输入前置】挡下 → 【回退】兜底 | 正常路由；`hints` 不提示、`ROUTES.md` 不标注 |
| **free**（自由文本） | 降级：仅关键词级匹配（**不保证**『不适用 / 回退』判断） | `hints` 提示"未结构化 → 降级匹配"；`ROUTES.md` 行内标 `（自由描述·降级匹配）`（**不静默**） |
| **empty**（未写） | 无：不参与路由 | `hints` 提示"补一句『何时用』即可被召回"；`ROUTES.md` 标 `（无描述·不可路由）` |

```text
【何时用】<什么任务场景该进这里；含任务关键词，便于词面命中>
【不适用】<什么情况不该进这里；→ 指向更合适的节点 id>
【别名】<别称 / 简称 / 同义说法；无则写「无」>
【输入前置】<需要的凭证 / 文件 / 权限；无需则写「无需 X」>
【时效性】<数据是实时 / T+1 / 随包更新…>
【回退】<这里解决不了时怎么办：→ 兄弟节点 / 父级 / 任务层亲做>
```

**自由描述的真实代价**（为什么仍推荐六段）：`【不适用】` 与 `【回退】` 是判据链"排除"与"兜底"的**唯一输入**——
没有它们，路由只能做关键词命中，可能误选相邻节点（例：要"应收边际利润"被"促销毛利"节点接走）。
所以：**写不写随你；不写就被显式标成降级匹配**（人工读图 / AI 读图都能一眼看见）。

## 8. 需求契约表（多阶段 / 长任务适用 · 引导级形状）

**何时用**（判据在 `flow/2-plan.md` 出口判据）：任务跨越 **≥3 个阶段**，或预计调用次数多、执行期长——**需求的"原话"容易被中段细节冲淡**时启用；单阶段小任务**不要**用（那是官僚化 ✗）。

**用途**：把**用户原话需求逐条**与"谁承接、证据在哪、现在什么状态"绑在一张表上；**每阶段出口勾选**、**交付前总核对**——防"把子目标当整体目标、完成局部就宣告完成"。

```text
| # | 需求原文（照录，不改写） | 承接阶段 | 证据指针（文件/命令/行） | 状态 |
| --- | --- | --- | --- | --- |
| R1 | <用户原话> | P1 / P3 | P-0x ｜ `03-结果交付区/xxx.xlsx#sheet1` | 完成 / 进行中 / 放弃（原因） |
| R2 | … | … | … | … |
```

**纪律（3 条）**：① **不缩水**：每条原话都要有行；不确定是否算"需求"的，宁可列上标"待确认"；② **不悬空**：交付前每条必须是"完成"或"放弃 + 原因"（写"进行中"不许交付）；③ **变了就改**：用户中途改需求 → 改表 + 记计划版本（`control.md`）。
