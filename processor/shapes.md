# 形状模板（按需读 · 引导级，非判据）

> **性质**：以下都是**引导**——照抄可以让表达更清楚，**但不是判据**；不用它们不影响验收。
> **何时读**：需要向用户提问、需要标注口径、需要写交付件时。
> **为什么单独放这里**：常驻的准则只放判据（保持精简），形状随用随取（渐进披露）。

## 1. 询问清单（② 规划 · L3 集中询问）

硬要求（在 `flow/2-plan.md` 动作 3）：每项 **2-3 个选项 + 差异与后果 + 默认建议**；一次任务最多一轮。

```text
【问】<L3 问题原文，一句话>
  A. <解读> —— 差异：改变哪部分结果；后果：影响哪个交付物
  B. <解读> —— 差异：…；后果：…
  → 建议 A（一句话理由）；你也可选 B 或给第三解
```

## 2. 口径标注（④ 验收 · ⑤ 交付）

硬要求（在 `flow/4-accept.md` 与 `flow/5-deliver.md`）：**不带口径的数字不出口**。

```text
| 指标   | 数值      | 口径（时间范围 · 主体 · 含税/去重 · 排除项）              |
| --- | --- | --- |
| 销售额 | 1,234 万 | 2026-08-01~08-31 · 药事业部 · 含税 · 剔除退款            |
```

## 3. 报告骨架（⑤ 交付）

硬要求（在 `flow/5-deliver.md` 动作 1）：**结论先行 + 五要素齐备 + 口径随行**。

```text
结论：<一句话，能独立成立>
关键发现
  1. <最重要，带口径>
  2. …
支撑细节
  <表格优先>
口径与假设
  <时间范围 / 主体 / 排除项 / 已知假设>
后续建议
  <只给有依据 + 可执行的>
```

## 4. 工作区结构（② 规划建齐 · 四区）

硬要求（在 `flow/2-plan.md` 动作 2）：**四区建齐、根目录只放四区**。

```text
<work-dir>/                     ← 用户指定优先；未指定则 work-<YYYYMMDD>-<任务短名>/
├── 01-原始材料区/              ← 用户材料（只读；同名加 -v2，不覆盖）
├── 02-任务执行区/              ← 过程记录.md（活文档）+ 临时产物区/
│   └── 临时产物区/              ← agent 产生的一切（脚本/中间数据/学习材料）只放这里
├── 03-结果交付区/              ← 只放最终件（命名 <用途>-<YYYYMMDD>.<ext>，无 final/v2）
└── 04-归档区/                  ← 历史/不适用/过时（不删除）+ IMPORT.md（归档条目表）
可选：README.md                 ← 一句话任务说明 + 四区索引（给人机双方的入口）
```

## 5. 过程记录骨架（v2 · 5 节 · 引导级形状，照抄即用）

硬要求（在 `flow/3-execute.md` 动作 3）：**实时追加**；结构本身是引导，可裁量。

```markdown
# 过程记录 · <任务短名>
> 工作区：<绝对路径> ｜ 开始：<YYYY-MM-DD HH:MM> ｜ 状态：进行中/已完成

## 1. 需求原文
<用户原话照录；下一行写我的复述（可被用户核对）>

## 2. 进度（SOAP 式：主观/客观/评估/计划）
- [完成] <客观事实：做了什么、产物在哪（P-nn）>
- [进行中] <现在做什么><预计><阻塞：等谁/等什么>
- [下一步] <计划（这是给"接手者"看的：换人/换会话照此续跑）>

## 3. 关键信息与口径（KI）
- KI-01 ｜ <事实> ｜ 口径：<时间/范围/单位> ｜ 来源：<文件/命令/资产 id>

## 4. 决策记录（D）
- D-01 ｜ <问题> ｜ 选项 A/B（含被排除者的理由）｜ 选定：<X> ｜ 时间

## 5. 产物与归档指针（P / A）
- P-01 ｜ <临时产物区/xxx.py> ｜ 用途 ｜ 状态：在用/已归档
- A-01 ｜ <阶段 X 完成> → 细节见 04-归档区/过程记录-阶段X.md（主记录只留折叠指针）
```
