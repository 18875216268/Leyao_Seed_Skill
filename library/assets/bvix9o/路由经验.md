# 路由经验（实测沉淀账本）

> 目的：把「什么需求 → 用哪个资产/工具 → 传什么参数与凭证 → 边界在哪」沉淀成可复用经验。
> 纪律：只记**实测或权威文档**支撑的结论；每条写清**边界**与**踩坑点**；未实测的放"待验证"。
> 最近更新：2026-09-12

---

## 1. 数据取数：时间跨度决定工具（促销毛利 vs BI 自定义）

- **作用**：按"要查多长时间"直接选对工具，避免拿 48 小时限制的工具去查整月。
- **规则**：

| 需求 | 用谁 | 边界与证据 |
| --- | --- | --- |
| 当天实时 / 单日 / 最多两日 | **PMS 促销毛利**（资产 `p3nes3` → 子包 `psol5x`） | 单次跨度 **≤48 小时**（超出被明确拒绝：`use a <=48h range or query each day separately`）；**当天数据可精确到秒级**；2026-09-12 实测 12/12 天成功（每日约 1 秒） |
| 月度 / 长跨度历史 | **观远 BI「出库统计Ultra」**（资产 `i7c4z1` → 子板 `h4dsa6`） | 主卡"自助查询结果-**每天 9 点前更新至昨天**"→ **T+1、截止昨天**；`date` 参数支持区间（未传时默认**出库日期本月第一天至昨天**）；月度数据 T+1 |
| 长跨度 + 含当天实时 | **混合（推荐）** | 历史段（本月 1 号 ~ 昨天）走 BI；当天（00:00 ~ 现在）走促销毛利；拼接时**对齐口径**（出库 vs 支付、含税口径、客户数去重、日界），并交叉校验 |

- **踩坑点**：
  - 促销毛利**不支持长跨度**（客户端直接拒绝；>48h 用 `--split-days` 或按天拆分后本地聚合）；
  - BI **不含当天**（T+1，每天 9 点前更新到昨天）——"今日实时"必须用促销毛利补；
  - 混合最易错的是**日界与去重**（BI 默认出库日期口径、促销毛利可挑选支付/出库口径；客户数不可跨日相加）。

## 2. 数据取数：凭证（两套独立，各自一处取全、各自一次登录）

| 系统 | 取用出口（一处取全） | 传给子包的方式 |
| --- | --- | --- |
| PMS | 父 `p3nes3`：`python scripts/pms_login.py --status` → token + 身份 + 公司 `provider_id` + 发货仓 `warehouses` | `--token` / `PMS_TOKEN` + `--provider-id` / `PMS_PROVIDER_ID` |
| BI | 父 `i7c4z1`：登录仓 `%LOCALAPPDATA%\bi-operations-query\accounts\<loginId>.json`（`python scripts/bi_login.py --status` 只验证、绝不弹窗） | `BI_UID_TOKEN` + `BI_UID_TOKEN_SIG`（可选 `BI_UID_EXP`）；或 `credential.local.json`；子板内自带**父登录器回退**（向上找 `scripts/login_bi.py`，不弹窗） |

- **边界**：两套系统**域与登录都不同**，凭证**不可互传**；各自登录一次后长期复用（PMS 实测**零二次登录** ✓；BI 凭证 2026-09-12 实测有效，至 09-26）。
- **踩坑点**：不要把 PMS token 传给 BI，反之亦然；混合任务要**先分别确认两侧凭证**再并行取数。

## 3. 取数口径与校验（少踩坑）

- **明细 vs 汇总必须交叉校验**：2026-09 实测明细比汇总多 **+2,041.67 元**，且**全部来自当天**（09-01~09-11 两口径完全一致）→ 疑"在途/未落账"，建议日终复算；
- **客户数是"当日去重"**：跨日**不可相加**；比率类指标按合计重算，不要对每日比率取平均；
- **分页/拆分**：促销毛利用 `--all-pages`（>48h 加 `--split-days`）；BI 关注 `isTruncated` 截断标记；
- **口径必须进交付物**：时间范围 / 公司 / 仓库 / 金额口径 / 数据快照时间——否则复盘数字无法复核。
