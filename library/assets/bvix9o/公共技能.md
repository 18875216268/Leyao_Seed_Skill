2.archify
-作用：提供美观且可验证的架构、工作流程、序列、数据流和生命周期图——自包含的 HTML 带动态和清晰导出；
-获取：https://github.com/tt-a1i/archify。

3.Humanizer-zh（op7418 · 去 AI 味 · 事后清洗 · 中文）
-作用：把 AI 写作的痕迹逐条清洗（拔高腔 / 堆名头 / AI 高频词 /「不是X而是Y」句式 / 滥用加粗 emoji 等）；汉化自英文原版 humanizer（46.5k★）：https://github.com/blader/humanizer ；繁体版 writing-humanizer（台湾正体）：https://github.com/shyuan/writing-humanizer。
-适用：已经写完了、想快速把明显的 AI 痕迹删掉。注意：清洗完文风中性——不像 AI 了，但也还不像你。
-获取：https://github.com/op7418/Humanizer-zh（安装：npx skills add https://github.com/op7418/Humanizer-zh.git）。

4.talk-normal（hexiecs · 去 AI 味 · 源头预防）
-作用：一段系统提示词，挂在生成之前，让模型从一开始就说人话——直接给答案，禁铺垫、禁废话、禁「不是X而是Y」句式、禁「综上所述」「希望对你有帮助」式收尾。
-适用：想少返工、从源头就不产生 AI 味。约束较狠，表达会偏干偏硬，需自己权衡。
-获取：https://github.com/hexiecs/talk-normal（安装：git clone https://github.com/hexiecs/talk-normal.git && cd talk-normal && bash install.sh；自动注入 AGENTS.md，卸载加 --uninstall）。

5.humanizer-zh（ai-zixun · 去 AI 味 · 模仿风格 · 做加法）
-作用：中文去 AI 味，同时往「你自己」靠：兼容 Codex / Claude Code / OpenClaw，深度改写可套 8 位中文作者声音（李笑来 / 鹤老师 / 罗振宇 / 吴军 / 李尚龙 / 何帆 / 冯唐 / 刘子超）；日常也可喂自己的旧文沉淀个人腔调。
-适用：想长期做个人 IP、建立辨识度——「你是谁」是清洗工具给不了的，只能靠自己的语料喂出来（四派里门槛最高、价值最大）。
-获取：https://github.com/ai-zixun/humanizer-zh（安装：npx skills add ai-zixun/humanizer-zh -g）。

6.humanizer-zh-academic（redbaronyyyyy-eng · 去 AI 味 · 降检测率 · 应试）
-作用：专门降低中文学术写作的 AIGC 检测率（论文 / 期刊 / 毕业论文），靠打破 AI 写作的模式规律性实现；精简版 SKILL.md 省 context，完整版 SKILL_full.md 改写更细。
-适用：有明确检测要求的场景（交论文 / 怕平台判定 AI 限流）。注意：降检测率 ≠ 写得好，别为了过检测把文章改得七零八落。
-获取：https://github.com/redbaronyyyyy-eng/humanizer-zh-academic（克隆仓库到宿主 skills 目录，如 Claude Code 的 ~/.claude/skills/）。

用法链路（推荐）：源头预防（少产生）→ 事后清洗（删残留）→ 模仿风格（变成你）；降检测率只在有明确检测要求时再叠加。
一句话：工具能做的都是「减法 / 过滤」——真正的人味（你的经历、你的观点、你的腔调）没有任何 Skill 能替你生成。

7.ian-xiaohei-illustrations（小黑 Skill · 把抽象观点变成图）
-作用：先读懂文章的认知锚点，再把其中一个判断 / 流程 / 状态 / 隐喻画成一张 16:9 白底手绘解释图——「小黑」（黑色实心、白点眼、细腿、空表情的小角色）必须承担核心动作、不能当装饰（例：把「业务痛点→项目复盘→经验萃取→课程设计→训练验证→业务改善」画成一张图，观点才真正被看见）。产出一篇文章 4~8 张 shot list（含主题 / 核心意思 / 结构类型 / 小黑动作 / 中文标注建议）+ PNG（存 `assets/<文章名>-illustrations/`）；不出 PPTX、可编辑矢量图、商业 KV。
-适用：写中文文章、知识型 / 方法论内容需要正文配图，想把抽象判断落成具体隐喻；不适合要商业插画、精致扁平风、传统 PPT 信息图或儿童卡通的场景。
-获取：https://github.com/helloianneo/ian-xiaohei-illustrations（MIT License；Codex Skill——`git clone` 后把 `ian-xiaohei-illustrations` 整个目录复制到 `${CODEX_HOME:-~/.codex}/skills/`，用 `Use $ian-xiaohei-illustrations …` 调用；CodeBuddy / Claude Code 同理放进各自 skills 目录）。同作者另有手绘 PPT 生成：https://github.com/helloianneo/ian-handdrawn-ppt。

8.find-skills（元技能 · 技能导购 · 本清单的"进货渠道"）
-作用：先把模糊任务拆成能力节点，再去技能生态里「搜 → 验 → 装」：主源 SkillHub 语义搜索（中英双语，lightmake.site），备源 Vercel Skills CLI（npx skills find）与 ClawHub（npx clawhub search）；顺序是先查本地市场再联网，装完必须验证落位（装到宿主的 skills 目录）。
-适用：需要「有没有做 X 的技能 / 帮我找个技能」时；它是本清单的进货渠道——本机实测：本地市场已缓存 295 个技能（含 humanizer、guizang-ppt-skill、deep-research 等），先查本地能省网络；SkillHub 中英双语搜索均可用。
-获取：CodeBuddy 官方插件，宿主已内置（~/.codebuddy/plugins/marketplaces/codebuddy-plugins-official/plugins/find-skills）；主源 https://lightmake.site ｜ 备源 https://skills.sh/ 、https://clawhub.com/ 。注意：其「本地市场优先」一步只写了 WorkBuddy 路径（~/.workbuddy/skills-marketplace/skills），CodeBuddy 实际在 ~/.codebuddy/skills-marketplace/skills（已实测存在）。
